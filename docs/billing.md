# Оплата: Stripe і сторінка цін

Специфікація — `../../doc/Специфікація_ Paywall, Прайсинг, Stripe Native & Java Backend.md`.

## Як змінити тріал, ціну чи текст плану

Пробний період: Stripe Dashboard → **Product catalog** → **Pulsar Kids Family** → праворуч **Metadata** → `trial_days` (зараз `7`) → змінити число → Save. За ≤ 5 хвилин сайт показує нове число («7 днів безкоштовно»), а Checkout дає новий тріал кожній новій підписці (наявні підписки свого тріалу не змінюють). Порожнє значення або `0` — без тріалу.

Так само в metadata продукту — назви (`name_uk` …), «для кого» (`tagline_uk` …), позначка (`badge_uk` …), рядки «що входить» (`feature_1_uk` …), хвилини безкоштовного плану (`daily_minutes`), діти в пакеті (`children_included`). Ціна — нова Price з тими самими metadata (стару архівувати).

## Де живуть плани

**У Stripe.** Сайт і гра не мають власних цін, назв планів чи списку «що входить»: API читає каталог зі Stripe (`GET /api/billing/plans`, `backend/…/core/Catalog.java`) і кешує його на 5 хвилин. Тому зміна в Stripe Dashboard з'являється на сторінці цін приблизно за 5 хвилин. Ціни, вписані в HTML під час збірки сайту (для пошуковиків), оновлюються з наступною збіркою.

Перший варіант каталогу створив `node ../scripts/stripe-setup.mjs`. Повторний запуск нічого не перезаписує; `--force` записує значення зі скрипта поверх того, що є в Stripe.

### Продукт (Stripe → Product catalog → продукт → Metadata)

| Ключ | Що це |
|---|---|
| `app` | `pulsar-kids` — без нього продукт не показується |
| `kind` | `free` (без оплати), `paid` (платний план), `extra_child` (доплата за дитину) |
| `order` | порядок карток: 1, 2, … |
| `plan` | лише для `extra_child`: id платного плану, до якого він додається |
| `name_uk`, `name_en`, `name_pl` | назва плану мовою (інакше — назва продукту) |
| `tagline_uk` … | рядок «для кого» під назвою |
| `badge_uk` … | позначка над карткою («Для всієї сім'ї»), необов'язково |
| `feature_1_uk`, `feature_2_uk`, … | «що входить», по рядку (так само `_en`, `_pl`); без них — Marketing features продукту |
| `daily_minutes` | хвилини на день у безкоштовному плані |
| `trial_days` | днів пробного періоду платного плану |
| `children_included` | скільки дітей у платному плані без доплати |

### Ціна (продукт → Pricing → ціна → Metadata)

| Ключ | Що це |
|---|---|
| `region` | id регіону: `UA`, `PL`, `US`, `CA`, `EU` — по одній ціні на регіон і період |
| `countries` | країни, що платять цю ціну: `AT,BE,DE,…` |
| `fallback` | `true` — регіон для всіх країн, яких не названо (зараз US) |
| `langs` | мови сайту, чия сторінка показує цей регіон першим (`uk`) |

Нова ціна в Stripe — це нова Price (суму наявної змінити не можна). Створи нову ціну з тими ж metadata, а стару архівуй. Підписки на старій ціні лишаються на ній.

## Два налаштування, яких немає в API — зробити вручну

### 1. Знижка при спробі скасувати підписку

Коли батьки натискають «Скасувати» в порталі Stripe, Stripe може спершу запропонувати −70 % на 1 місяць (купон `RETENTION_70_1M` уже створено; рішення власника від 2026-10-16 замість −70 % на 3 місяці зі специфікації). Увімкнути це можна лише в Dashboard:

1. Stripe Dashboard → ⚙️ **Settings** → **Billing** → **Customer portal** (тестовий режим: https://dashboard.stripe.com/test/settings/billing/portal).
2. Розділ **Cancellations** → увімкнути **Retention coupon** (або «Offer a coupon»).
3. Вибрати купон **RETENTION_70_1M** → **Save**.

Увага щодо річного плану: купон «на 1 місяць» Stripe застосовує до рахунку, виставленого в цей місяць. Для річної підписки це наступний річний рахунок, тобто −70 % від цілого року. Якщо так не годиться, потрібен окремий купон для річних (−6 % ≈ 70 % від однієї дванадцятої) і правило утримання (Retention rules) за інтервалом підписки.

### 2. Що робити, коли платіж не пройшов

Специфікація (§4.5) хоче дві спроби за 8 і 20 годин, але **Stripe не вміє повторювати платіж через години**. Власний розклад — до трьох спроб, кожна через ціле число днів після попередньої. Найближче до «доби»:

1. Stripe Dashboard → **Revenue recovery** → **Retries** (тестовий режим: https://dashboard.stripe.com/test/revenue_recovery/retries; старий шлях Settings → Billing → Subscriptions and emails тепер веде сюди).
2. Замість **Smart Retries** вибрати **Custom retry schedule**.
3. Одна повторна спроба через **1 день** (або дві: через 1 день і ще через 1 день — тоді вікно 2 доби).
4. **If all retries for a payment fail** → **Cancel the subscription** → **Save**.

Точно 24 години з годинними спробами можна зробити лише своїм кодом: вебхук `invoice.payment_failed` → повтор платежу через API → скасування. Це частина майбутньої роботи з вебхуками.

Обидва налаштування окремі для тестового й бойового режимів: після активації бойового акаунта їх треба повторити там.

## Платний режим

Адмінка → «Налаштування» → **💳 Платний режим** — один перемикач для всього, що стосується оплати. За замовчуванням вимкнено.

- **Вимкнено:** Pulsar Kids повністю безкоштовний. Сторінки цін і посилань на неї немає, `/api/billing/plans` не віддає планів, у грі немає ліміту, пейволу й оплати.
- **Увімкнено:** сторінка цін з планами зі Stripe, а коли їх буде зроблено, — Checkout, ліміт безкоштовного плану й пейвол.

Вимкнено — не працює **нічого** з оплати: сторінка цін і посилання, вікно планів на сайті, пейвол і оплата в грі, вибір і зміна плану, портал Stripe (API відповідає `billing_off`). Виняток один: вебхуки Stripe приймаються й далі, бо вимкнення режиму **не скасовує** підписок у Stripe — вони продовжують списувати гроші, і сім'ї отримують рахунки. Картка в адмінці попереджає, скільки таких підписок; скасувати їх — у Stripe → Billing → Subscriptions.

Сайт і гра дізнаються про зміну за пів хвилини (`features.paid` у `/api/health` та `/api/state`). Кожна нова платна функція спершу перевіряє цей перемикач.

## Ключі

- `STRIPE_SECRET_KEY` — на бекенді (`game/.env.local` локально; Vercel-проєкт `pulsarkids-api` у продакшні). Зараз це ключ **sandbox** (`sk_test_…`).
- `VITE_STRIPE_PUBLISHABLE_KEY` — для Checkout у грі (ще не використовується).
- Адмінка → «Налаштування» → картка «🔌 Stripe» показує режим, акаунт і що є в каталозі.

## Шлях сім'ї до оплати

1. Сайт → «Ціни» → вікно з двома планами (ціни регіону відвідувача, рік / місяць, кількість дітей) → **«Розпочати пригоду»**.
2. Перехід на вхід у кабінет батьків з диплінком: `https://parents.pulsarkids.com/parent-login?plan=family&period=year&children=3` (+ `&offer=КОД`, якщо відвідувач прийшов із промокодом).
3. Після входу (чи реєстрації) пейвол у кабінеті одразу відкриває **оплату**: зліва — платіжна адреса й картка (поля Stripe; лише картка, Apple Pay і Google Pay — без Link), справа — підсумок: план, діти, «7 днів безкоштовно», до сплати сьогодні, наступне списання, поле промокоду.
4. Після оплати — «Пригоду розпочато», план Family на акаунті (вебхук Stripe), лист із рахунком на пошту після першого списання.

Хто зареєструвався в грі напряму, без вибору плану: перший вхід — нічого; з другого входу — **обов'язковий** вибір плану (Базовий або Family), вікно не закривається.

## Диплінки й промокоди

| Параметр | Значення |
|---|---|
| `plan` | `family` (платний) або `basic` (безкоштовний — стає планом акаунта; новому акаунту, що ще не мав плану, один раз показується вікно з пропозицією спробувати Family, яке можна закрити) |
| `period` | `year` / `month` (за замовчуванням рік) |
| `children` | кількість дітей (не менше, ніж у пакеті) |
| `offer` | промокод зі Stripe |

Промокод створюється в Stripe: Product catalog → Coupons → купон → **+ Add promotion code**.
- Знижковий купон (−30 %, −50 % на N місяців…) — застосовується в оплаті, видно в підсумку.
- Купон **−100 % назавжди** (як `VIP_100_FOREVER`) — Family **у подарунок**: жодної форми оплати, жодних обмежень. Приклад посилання: `https://parents.pulsarkids.com/parent-login?offer=FRIENDS`.
- **Забрати подарунок:** деактивуй промокод у Stripe (promotion code → Archive / Deactivate) — за ≤ 5 хвилин подарунок знімається, і сім'я бачить пейвол (або свій попередній план). Або в адмінці → «Акаунти» → кнопка 🎁 (подарунок від власника, вмикається й вимикається там само).
- Недійсний чи вичерпаний код: «На жаль, ваш оффер не є активний», і оплата відкривається без знижки.

## Керування підпискою в кабінеті

«💳 Підписка»: поточний план, тріал / наступне списання; кількість дітей ±; річна ↔ щомісячна оплата (Stripe перераховує пропорційно); «Перейти на Базовий» — наприкінці оплаченого періоду (червоний банер з датою, «Відновити підписку»); «Картка й рахунки» — портал Stripe.

## Назва в платіжній формі

Stripe пише в формі «By subscribing, you authorise **<назва акаунта>** to charge you…». Зараз там «- sandbox», бо так названо тестовий акаунт. Зміни: Stripe Dashboard → ⚙️ Settings → **Business** → **Public details** → *Public business name* = `Pulsar Kids` (окремо в тестовому й бойовому акаунтах).

## Тестові картки (лише для перевірки власником; на сторінках про тестовий режим нічого не пишеться)

`4242 4242 4242 4242`, будь-яка майбутня дата, будь-який CVC; `4000 0025 0000 3155` — з 3-D Secure; `4000 0000 0000 9995` — відмова.

## Рахунки на пошту

На кожну оплату Stripe створює рахунок (номер, PDF, сторінка рахунку). Stripe повідомляє API (`POST /api/billing/webhook`, подія `invoice.paid`), API зберігає рахунок у `wk_billing_invoices` і надсилає сім'ї лист мовою сторінки, на якій вона платила (через Resend). Пробний період (рахунок на 0) листа не дає; повторна подія не дає другого листа. Адмінка → «Налаштування» → **🧾 Рахунки на пошту** вимикає листи (за замовчуванням увімкнено).

Вебхук зареєстровано в Stripe (тестовий режим) на `https://api.pulsarkids.com/api/billing/webhook`; його секрет — `STRIPE_WEBHOOK_SECRET` у Vercel. Власні листи Stripe про оплату (Settings → Customer emails → Successful payments) лиши **вимкненими**, інакше сім'я отримає два листи. Локально: `stripe listen --forward-to localhost:4323/api/billing/webhook`.

## Податки

Ціни в Stripe — «податок включено» (`tax_behavior: inclusive`): сім'я платить рівно те, що бачить. **Крім США**: там ціни без податку (`exclusive`), а податок з продажів додається зверху там, де штат його вимагає (сайт пише це під ціною). Stripe Tax вмикається в Checkout **сам**, щойно в Stripe з'явиться активна податкова реєстрація (Dashboard → Tax → Registrations). До того податок не нараховується.

Коротко про правила (перевір із бухгалтером, бо оператор — польська фірма):

- **Польща:** ПДВ 23 %, якщо фірма платник ПДВ (звільнення до 200 000 зл на рік для малого бізнесу).
- **ЄС (крім Польщі), споживачі:** до 10 000 € продажів на рік в інші країни ЄС — польський ПДВ; понад це — ПДВ країни покупця через OSS. Для цього й потрібна платіжна адреса: вона доводить країну покупця.
- **Україна:** нерезидент, що продає електронні послуги фізособам, реєструється платником ПДВ (20 %), коли продажі перевищать 1 млн грн за 12 місяців.
- **США:** податок з продажів на цифрові послуги залежить від штату; обов'язок виникає після порогу в штаті (зазвичай 100 000 $ або 200 продажів на рік).
- **Канада:** GST/HST для нерезидентів після 30 000 CAD за 12 місяців.

Stripe Tax → Monitoring сам показує, де наближаються пороги.
