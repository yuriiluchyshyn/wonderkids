# Прийом документа гри і нова гра з нього

Документ — один файл `<gameId>.md` від skill-у `game-task-pack`: паспорт гри, розділи
`## Рівень N` з блоками ```json завдань і розділ `## Перевірка`. Твоє завдання — перевірити
його, перенести вміст у код **програмно, без переписування руками**, і довести гру до кінця:
вона грається, перевірена всіма мовами і має свою сторінку на сайті.

Перед роботою прочитай `CLAUDE.md` і `docs/level-design.md`: їхні правила сильніші за цей skill.
Задача велика — роби всі етапи підряд, не зупиняйся між ними (крім двох запитань нижче).

---

## Етап 0. Місце гри і що спитати

**Місце бери з паспорта** (`місце:`) і звір його з Додатком А та кодом:

- **`new-game`** — нова гра в наявному розділі `game/src/games/<subject>`. Перевір, що такого `id`
  там ще немає і що гра не повторює наявну (Додаток А). Повторює — скажи людині до початку роботи.
- **`extend`** — розширення наявної гри. Прочитай її `tasks.ts` / `content/` і зроби висновок:
  - її завдання лежать списком (пул, рейтинг) — завдання пакета додаються до неї, `steps` росте,
    рівні пакета йдуть після її останнього; `key` пакета не збігаються з її `key`;
  - її завдання генеруються кодом (математика, «рамка × оболонка») — пакет так не ляже; опиши
    людині, як влити його (нова рамка, нова стадія), і роби лише після «так».
  Прогрес дітей прив’язаний до `id` гри — **id не змінюй**.
- **`new-galaxy`** — новий розділ: папка `src/games/<subject>` за зразком `games/nature`
  (`index.ts`, `config.ts`, `tasks.ts`, `content/`, `grammar/`), рядок у `GALAXIES`
  (`src/core/game/galaxies.ts`; галактика «Скоро» з таким `id` отримує `moduleId` і втрачає
  `comingSoon`), імпорт у `src/games/index.ts`, назва `galaxy.<id>` у `common.json` кожної мови,
  на сайті — картка розділу в `site/index.html` (`#games`) і його `about` у JSON-LD.

Спитай у людини лише те, чого немає в паспорті, — завжди **дату публікації** (`publishDate`:
до неї гра в хабі «Скоро», 60 днів після — «NEW»). Решти бракує — спитай, а не вигадуй.

## Етап 1. Прочитати і перевірити документ

Напиши (або візьми наявний) скрипт `game/scripts/pack.mjs`. Він розбирає документ:
паспорт → об’єкт, кожен блок ```json під `## Рівень N` (або `## Завдання`) → масив завдань.
Тим самим скриптом робиться і перенесення (етап 3), тож він потрібен один раз на всі майбутні ігри.

Перевір, і **кожну проблему випиши людині списком** (id завдання + що не так):

| Що | Правило |
| --- | --- |
| Формат | перший рядок `<!-- game-task-pack v1 -->`; кожен JSON розбирається |
| Кількість | завдань стільки, скільки в «Математиці» паспорта; `id` — `T0001…` без пропусків |
| Рівні (шлях) | `level` 1…steps; рівень 1 має ≥ `tasksPerLevel` завдань, кожен інший ≥ половини `tasksPerLevel` |
| Унікальність | `key` унікальні; два завдання з тим самим запитанням в іншому оформленні — це одне |
| Варіанти | `correctId` є серед `options`; `UI_GRID_CHOICE` — 9 варіантів або 6 (картинка + назва), ніколи 4 |
| Хибні варіанти | лише з того, що відкрито на рівнях ≤ `level` цього завдання |
| Підказки | рівно 3, різні, жодна не порожня й не «подумай ще раз»; 1–2 не містять відповіді |
| Факти | рівно 3 (якщо факти є в паспорті), жоден не повторюється в усій грі |
| Мови | кожен текст має всі мови паспорта; в `en` / `pl` немає кирилиці; немає `undefined`, `TODO`, `…` |
| Тон | немає «неправильно», «помилка», «програв», страшного; гроші — без назви валюти |
| Зображення | кожен `img` описаний у `images` (один раз на гру); є `where`, `kind`, `source`, `describe`, `emoji`, `cue`; реальна людина — не `ai` |

- Дрібниці (зайвий пробіл, лапки) виправ сам і перелічи, що виправив.
- Якщо проблем у вмісті багато (дублі, бракує завдань, хибні варіанти з майбутніх рівнів) —
  **зупинись** і спитай: людина перегенерує ці завдання в `game-task-pack` чи ти виправляєш сам.
- Факти, у яких сумніваєшся (цифри, дати, «найбільший»), покажи людині окремим списком.

## Етап 2. Підказки по драбині — у рушії, один раз

Документ дає по 3 підказки на завдання, які мають відкриватися по черзі. Перевір, чи рушій уже
це вміє: шукай поле `hints` у `TemplateBase` (`src/core/game/templates/types.ts`).

**Якщо ще не вміє** — додай один раз, загально для всіх шаблонів, щоб наявні ігри не змінилися:

- `TemplateBase.hints?: string[]` — драбина. Гра без неї працює як раніше (`hint`).
- Підказка з’являється, як і зараз, після `HINT_THRESHOLD` помилок (або однієї на повторі
  завдання), далі кожна наступна помилка відкриває наступну сходинку:
  `rung = min(hints.length − 1, mistakes − поріг)`. Рахуй це поруч із `hintActive`
  у `src/components/game/useGameSession.ts` і віддай як `session.hintRung`.
- Озвучення: `getHintSpeech` (у `SHARED_SCREENS`, `games/shared/templateModule.ts`) читає
  `hints[rung]`, а не `hint`; нова сходинка вимовляється, щойно відкрилася.
- **Завдання з драбиною не звужує варіанти** — так само, як завдання з `counting` чи `clue`
  тримає всі відповіді на дошці. Звуження — лише якщо третя підказка має `"board": "narrow"`.
- `"board": "pulse:answer"` — та сама пульсація цілі, що й зараз робить шаблон із `hintActive`;
  інших значень `board` не вигадуй — нове значення є лише тоді, коли шаблон його вміє.
- Тест у `game/tests/` на правило сходинок (чиста функція, без React) і рядок про драбину
  в `CLAUDE.md` (розділ про Zero-aggression / hints) та в `docs/level-design.md` §5.

## Етап 3. Перенести вміст у код — скриптом

Жодного тексту в `.ts` (правило `CLAUDE.md`): тексти — у JSON мов, у коді — лише ідентифікатори,
рівні, emoji, відповіді. `pack.mjs import <file.md> --subject <subject> --game <sub>` пише:

1. **`src/games/<subject>/content/<sub>.ts`** — дані без слів, у порядку `id`:
   ```ts
   /** «<Назва>» — made by scripts/pack.mjs from <gameId>.md; do not edit by hand. */
   export const TASKS: PackTask[] = [
     { id: 'T0001', key: 'planet-color:mars', level: 1, mechanic: Mechanics.GridChoice,
       options: [{ id: 'a', emoji: '🔴' }, …], correctId: 'a', board: [null, null, 'pulse:answer'], own: false },
   ];
   ```
   `Mechanics.X` — член enum, ніколи рядок `'UI_GRID_CHOICE'`.
2. **`src/locales/app/<lang>/games/<subject>.json`** — розділ `<sub>` у кожній мові паспорта,
   за `id` завдання: `{ "T0001": { "prompt": "…", "options": { "a": "…" }, "hints": ["…","…","…"], "facts": ["…","…","…"] } }`.
   Решту файлу не чіпай (скрипт зливає, а не переписує). Текст із `"own": true` обгорни
   `own(...)` у граматиці мови (див. нижче), щоб голос іншої мови його не читав.
3. Скрипт можна запускати знову: той самий документ дає той самий результат.

Потім напиши руками (це невелике):

- **`games/<subject>/grammar/`** — для кожної мови функція `pack<Sub>(id)` → тексти завдання з JSON
  (`fill` для `{currency}` та інших дірок; гроші — `currencyOf(config.currency)`). Якщо предмет новий —
  `types.ts`, `uk.ts`, `en.ts`, `pl.ts`, `index.ts` за зразком `games/nature/grammar`.
- **`games/<subject>/tasks.ts`** — `pool(step, config)`:
  - шлях — усі завдання з `level ≤ step`; нові/повторення рушій визначить сам (`recallLevel`);
  - вільна гра — усі завдання;
  - кожне через `templateTask(key, prompt, payload, step, facts)`; payload будується з
    `content/<sub>.ts` + тексти мови: картки `card(id, emoji, label)`, `correctId`, `cols: 3`
    (9 варіантів) або `cols: 2` (6), `hint: hints[0]`, `hints`, `outro` — три факти.
  - якщо в предметі вже є `TASKS` — додай гру під її `id`.
- **`games/<subject>/config.ts`** — картка в `GAMES`: `id`, `gameId` (з паспорта), `label`, `icon`,
  `blurb` (що дитина робить і з чим — речення, не три слова), `intro`, `langs` (= мови паспорта),
  `steps` (шлях), `progression`, `difficulty` (вік: 4–6 → 1, 6–8 → 2, 8–10 → 3), `publishDate`,
  `tasksPerLevel`, `mechanics`, `hasText`. Слова картки — у `config` JSON українською
  і в `cards` англійською / польською.

**Нова механіка** (паспорт описує дошку, якої немає в `Mechanics`) — це не вміст, а новий шаблон
у `components/templates` + `core/game/templates`. Зупинись після етапу 1, опиши план шаблону
людині і роби його лише після «так».

## Етап 3а. Зображення

Якщо в паспорті `зображення: так`. `pack.mjs images <file.md>` виписує список усіх `images`
(id, де, що, звідки) — з нього і працюй. Гра показує `Card.image` / `stimulus.image`
(шлях від `public/`), а поки файлу немає — `emoji`.

- **Куди:** `game/public/<папка гри>/<img id>.webp` — квадрат **224 px**, WebP, кілька КБ
  (як `public/people`, `public/things`). У папці — `CREDITS.md`: таблиця «File | Commons file |
  Licence | Author», рядок на **кожен** файл.
- **`commons`** — знайди файл за `search` / `describe` на Wikimedia Commons, візьми лише вільну
  ліцензію (CC0, CC BY, CC BY-SA, суспільне надбання), обріж у квадрат, збережи 224 px WebP,
  впиши рядок у `CREDITS.md`. Не знайшов чесної картинки або твір під авторським правом —
  лишай емодзі й додай у список людині.
- **`owner`** — дай людині список (id + опис + куди покласти) і чекай файли; до того — емодзі.
- **`ai`** — дай людині список описів для генерації (не реальні люди); файли кладуться так само,
  у `CREDITS.md` — «AI-generated».
- **`svg`** — малюнок у коді (як `PlanetArt`, `LandmarkArt`), лише коли він простий; складний —
  спитай людину.
- **`cue: true`** — картку загорни в `asCue(card)` (`core/game/cues`): картинка зникатиме після
  двох чистих відповідей. `cue: false` — не загортай.
- Наприкінці скажи людині, яких картинок ще бракує (id + опис), — гра з ними вже працює на емодзі.


Кожен `own`-текст англійською чи польською додай у `TODO.md` у список для вичитки носієм.

`npm run catalog` заодно оновлює Додаток А в обох skill-ах (`game/scripts/skills-catalog.mjs`):
перевір, що нова гра (і новий розділ) там з’явилися. Якщо змінилися правила, яких дотримується
вміст (нова дошка в `Mechanics`, драбина підказок, нове поле завдання), — допиши їх у §3–§6
`game-task-pack/SKILL.md` і в цей skill.

**Не деплой і не комітить без прохання.** Наприкінці скажи людині, що лишилося зробити їй:
задеплоїти сайт і гру разом (`../scripts/deploy.sh`) і знову подати `sitemap.xml` у Google Search
Console та Bing Webmaster Tools.
